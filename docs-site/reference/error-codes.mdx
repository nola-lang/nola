Nola diagnostics use stable codes:

- `NOLA1xxx`: parse errors, reported by the editor, `nola check` and `nola build`.
- `NOLA2xxx`: compile errors, reported by the same tools.
- `NOLA3xxx`: runtime errors from the runtime, loader or a provider.
- `NOLA4xxx`: build-time errors from bundler plugins.

Each code has a permanent link, such as `/docs/reference/error-codes/#nola2001`. Codes marked *not raised* are reserved or retired and will not be reused.

**Parse errors (NOLA1xxx)**

## NOLA1001

> *(the parser's own message)*

**Cause:** a syntax error without a more specific Nola code, such as an unbalanced brace or stray token.
**Fix:** check the location in the message and correct the TypeScript or JavaScript syntax.

## NOLA1003

> `ask` is a reserved word in .tsi files and cannot be used as an identifier.

**Cause:** `ask` used as a variable, function or parameter name.
**Fix:** rename it. `ask` stays legal as a member or property name (`obj.ask`).

## NOLA1004

> this Nola construct is reserved for a future Nola version.

**Cause:** syntax reserved for future use: an `infer` generator (`infer function*`), a marker on a class method, a bodiless `infer function`, or the derive-all call `fn(..)`. See [Restrictions](/docs/language/restrictions/) for other reserved forms.
**Fix:** use a top-level `infer function` declaration and write each call-intent argument as an explicit extractor (`` ..`…`: T ``).

`infer` on an arrow or function expression produces `NOLA1001` instead. It is a keyword only directly before `function` at statement or export position.

## NOLA1005

> expected a template literal prompt after `..`.

**Cause:** `..` followed by something other than a backtick instruction.
**Fix:** write `` ..`instruction`: T ``.

## NOLA1006

Not raised — reserved (`infer` without a following `function` is reported as `NOLA1001`).

## NOLA1007

> a marker after a plain function's name is not valid — only an `infer function` has that slot, and there it is reserved (NOLA1019).

**Cause:** a backtick literal between a plain function's name and its parameter list.
**Fix:** drop it; a plain function takes no marker. For an infer function, write the text as a context statement in the body ([Context statements](/docs/language/context-statements/)).

## NOLA1009

> expected a model name after `ask with` — for a dynamic model use `.withModel(...)` on the intent.

**Cause:** a string literal, a number or a parenthesized expression after `with` — anything that is not a bare identifier. (A dotted name such as `provider.fast` is parsed as the identifier `provider` followed by a stray `.fast`, so it reports `NOLA1005`/`NOLA1001` rather than this code.)
**Fix:** name the model in `nola.config.ts` and use that bare identifier; for a dynamic choice use `.withModel(…)`.

```tsi
// not-checked — WRONG
export infer function summarize(.text: string, useFast: boolean) {
  const a = ask with "fast" ..`a rough summary`: string;
  const b = ask with (useFast ? "fast" : "careful") ..`a rough summary`: string;
  return { a, b };
}
```

```tsi
// summarize.tsi — RIGHT
export infer function summarize(.text: string, useFast: boolean) {
  const c = ask with fast `a rough summary`: string;
  const d = ask (..`a rough summary`: string).withModel(useFast ? "fast" : "careful");
  return { c, d };
}
```

## NOLA1010

> `.` context parameters are only allowed on infer function parameters.

**Cause:** a `.name` parameter on a plain function, or a `.name` binding outside an infer body / the module body — there is no inference context to put the value in.
**Fix:** drop the dot (it is an ordinary argument or variable), or make the function an `infer function`.

```tsi
// not-checked — WRONG
function summarize(.text: string) {
  return text.slice(0, 10);
}
```

```tsi
// summarize-right.tsi — RIGHT
export infer function summarize(.text: string) {
  return ask `a one-sentence summary`: string;
}
```

## NOLA1011

> `.` on this parameter form is reserved for a future Nola version — use a plain identifier parameter.

**Cause:** `.` on a destructuring pattern or a parameter with a default value.
**Fix:** use a plain identifier parameter (`.issue: Issue`) and destructure or default inside the body.

## NOLA1012

> incomplete `.` context parameter — write `.name`.

**Cause:** a `.` with no parameter name after it (usually mid-typing).
**Fix:** finish the name.

## NOLA1013

> contextual parameters take one dot — write `.name` (`..` is the extractor sigil).

**Cause:** `..name` on a parameter.
**Fix:** use one dot: `.name`. Two dots introduce an extractor.

## NOLA1014

> `var .x` is reserved — a contextual binding is `const .x` or `let .x`.

**Cause:** the dot on a `var` declaration — `var` hoists to `undefined`, which no ask should see.
**Fix:** write `const .x` or `let .x` — see [Contextual bindings](/docs/language/contextual-parameters/#contextual-bindings).

## NOLA1017

> the implied extractor needs whitespace before its template — write `` ask `…` `` (`` ask`…` `` reads as a tagged template).

**Cause:** a template literal glued to `ask` (or to the model name after `ask with`) — `` ask`the user's name`: string ``. Without the space it reads as a tagged template call on `ask`, which is not what runs.
**Fix:** put at least one space (any whitespace) between `ask` and the backtick, or write the explicit sigil — `` ask ..`…`: T ``. See [Extractors](/docs/language/extractors/).

## NOLA1018

> expected a type after the extractor's `:` on the same line — write `` `…`: T ``.

**Cause:** a colon after an extractor's closing backtick starts its type, and nothing type-like follows it on that line — `` ask `the user id`: `` at the end of a line, or `` ask `the user id`: ; ``. The type has to start on the colon's line because TypeScript's type grammar reads across line breaks: otherwise an unfinished `:` above an existing statement would swallow that statement's first expression as a type name.
**Fix:** write the type right after the colon — `` ask `the user id`: number `` — or use the angle-bracket spelling, `` ask `the user id`<number> ``. See [Extractors](/docs/language/extractors/#the-angle-bracket-spelling).

## NOLA1019

> the marker after an infer function's name is reserved for a future Nola version — write the instruction as a context statement in the body: `…`.

**Cause:** a backtick literal between an infer function's name and its parameter list — `` infer function f`…`(…) ``. That slot no longer carries the instruction.
**Fix:** write the text as a context statement in the body ([Context statements](/docs/language/context-statements/)):

```tsi
// triage.tsi
export infer function triage(.ticket: string) {
  `triage the ticket like a support lead`
  return ask `the severity: low, medium or high`: "low" | "medium" | "high";
}
```

## NOLA1020

> a value in a context statement is a name, a call or a bracketed expression, followed by text or the end of the statement — wrap anything else in parentheses, or assign it to a local first (`await`, `ask` and `this` cannot be values).

**Cause:** after the text of a [context statement](/docs/language/context-statements/), a token that cannot continue it on the same line: an operator or an arrow after a value (`` `total` a + b ``, `` `map` x => x ``), or `typeof`, `void`, `await`, `ask`, `this`, `..`, `function` or `class` where a value would start. Also a value that ends with a backtick, which takes the text after it for a tagged template: `` `x` foo<string> `more` ``, `` `x` new Foo `more` ``. The same code, with its own wording, covers an [ask sequence](/docs/language/extractors/#values-in-the-instruction): `this`, `await`, `ask`, `function` or `class` where a value would start after a text, a value ending in a backtick, and text after the type (`` ask `p`: T `more` `` — the type ends the sequence).
**Fix:** parenthesize the expression — `` `total` (a + b) ``, `` `x` (foo<string>) `more` ``, `` `x` (new Foo) `more` `` — or put it in a `${}` hole of the text. `await`, `ask` and `this` cannot go in a value even in parentheses: a parenthesized `ask` is [`NOLA2010`](/docs/reference/error-codes/#nola2010), and a parenthesized `await` or `this` is a TypeScript error (`TS1308`, `TS2683`), because a context statement is read at each ask, outside the async body, in a hoisted function of its own. Compute the value first, assign it to a local and write its name: `const user = this.user;`, then `` `Page` user ``.

```tsi
// not-checked — WRONG
export infer function total(.items: string[], a: number, b: number) {
  `total` a + b `items`;                    // an operator after a value
  return ask `a summary`: string;
}
```

```tsi
// total.tsi — RIGHT
export infer function total(.items: string[], a: number, b: number) {
  `total` (a + b) `items`;
  return ask `a summary`: string;
}
```

## NOLA1021

> a tool list holds functions — a name, a member, an expression that is one function, or a group (a module or an object of functions, an array of them), bare or spread; a literal cannot be one, and the list is not empty.

**Cause:** a literal between the brackets of a tool list — `` ask `find the files` [1, "x"]: string[] ``, an arrow function, an object or array literal, a template, `new` — or an empty list, `` ask `p` []: T ``.
**Fix:** put the function or the group behind a name: `` ask `find the files` [searchFiles, fileTools]: string[] ``, or spread a group, `` [...fileTools] ``. See [Tool use](/docs/language/tool-use/#the-tool-contract).

## NOLA1022

> a call or a tagged template in a tool list is reserved for a future Nola version — name the function (`getUser`); its arguments come from its signature.

**Cause:** an entry written as a call, describing the arguments in place — `` ask `get the user` [getUser(`user id`: string)]: User `` — or as a tagged template. The shape is reserved.
**Fix:** write the name alone, `` ask `get the user` [getUser]: User ``; the model fills the arguments from the function's signature and JSDoc. See [Tool use](/docs/language/tool-use/#the-tool-contract).

## NOLA1023

> a colon-typed extractor directly in a ternary's consequent (a colon on the extractor's line is its type, spaced or not) — parenthesize it: `` cond ? (ask `p`: T) : y ``.

**Cause:** `` cond ? ask `p`: number : y `` — an extractor typed with the colon spelling stands bare between a conditional's `?` and `:`, so two colons with different meanings sit side by side; and since a colon after the extractor is its type whether glued, spaced or on the next line, `` cond ? ask `p` : y `` reads `y` as the type and the conditional has no alternate left — the formatted `` cond\n  ? ask `p`\n  : y `` reads the same way. An untyped ask is never valid, so neither shape could have meant anything else.
**Fix:** parenthesize the ask and give it its type: `` cond ? (ask `p`: number) : y ``. A call intent and the angle-bracket spelling (`` cond ? ask `p`<number> : y ``) need no parentheses, and the alternate position is unaffected: `` cond ? y : ask `p`: number ``.

**Compile errors (NOLA2xxx)**

## NOLA2001

> `ask` is only allowed directly inside an infer function body or the module body.

**Cause:** `ask` inside a plain function or a nested closure — even one written inside an infer function — or in a class field initializer / `static` block, where `await` is illegal.
**Fix:** ask directly in the infer body or at the top level of the module; from plain TS, `await` the infer function instead. Constructing an extractor anywhere is fine — only resolving it is restricted.

```tsi
// not-checked — WRONG
const g = async () => ask `the kind`: string;         // plain closure

export infer function f(.t: string) {
  const h = () => ask `the kind`: string;             // nested closure
  return h();
}
```

```tsi
// kind.tsi — RIGHT
export infer function f(.t: string) {
  return ask `the kind`: string;
}
```

## NOLA2002

> unsupported type for intent schema: …

**Cause:** an extractor's type resolves to a type the checker-backed derivation cannot turn into a JSON Schema — `Map`, `Set`, `Promise`, `RegExp`, functions, a generic used without arguments — or a member of it does; the message names the member and the type.
**Fix:** ask for a JSON-shaped type and convert afterwards in plain TypeScript. See [Schema derivation](/docs/reference/schema-derivation/).

```tsi
// not-checked — WRONG
export infer function tally(.doc: string) {
  return ask `counts per label`: Map<string, number>;
}
```

```tsi
// tally.tsi — RIGHT
export infer function tally(.doc: string) {
  const counts = ask `counts per label`: { label: string; count: number }[];
  return new Map(counts.map((c) => [c.label, c.count]));
}
```

## NOLA2003

> infer functions must be declared at module top level.

**Cause:** an `infer function` declared inside another function or block.
**Fix:** move it to module level.

## NOLA2004

> an extractor used as a call-intent argument must have an explicit type — write ..`…`: T here.

**Cause:** a call-intent slot written as `` ..`…` `` with no type. (A bare template with no type, `` createTicket(`a short ticket title`, 2) ``, is a plain string argument, not a slot: the call stays an ordinary call.)
**Fix:** give every slot a type, `` `…`: T `` (or `` `…`<T> ``); the `..` is implied in a call's argument list.

```tsi
// not-checked — WRONG
declare function createTicket(title: string, priority: number): Promise<string>;
export infer function fileTicket(.request: string) {
  return ask createTicket(..`a short ticket title`, 2);
}
```

```tsi
// file-ticket.tsi — RIGHT
declare function createTicket(title: string, priority: number): Promise<string>;
export infer function fileTicket(.request: string) {
  return ask createTicket(`a short ticket title`: string, 2);
}
```

## NOLA2007

> "./x.tsi" names neither a Nola file nor a TypeScript module

**Cause:** a relative `.tsi` import — written by you in a `.ts` file, or generated for a type a `.tsi` imports — found no `x.tsi`, `x.ts` or `x.d.ts` next to the importer.
**Fix:** check the specifier. `./models.tsi` means the Nola file `models.tsi` when it exists, otherwise the [view](/docs/language/types-as-values/#views-of-plain-typescript) of `models.ts`. See [TypeScript interop](/docs/language/typescript-interop/#types-from-another-file).

## NOLA2008

> contextual parameter '…' has a type that cannot be derived for inference: …. Set compiler.underivableContextType to "prune" or "omit" in nola.config.ts to allow it.

**Cause:** a `.param` whose resolved type is not derivable (same rules as `NOLA2002`); its value would have to be serialized into the prompt. The message names the offending member.
**Fix:** pass a JSON-shaped view, keep the exotic value as a plain parameter, or relax `compiler.underivableContextType` — see [Contextual parameters](/docs/language/contextual-parameters/#when-a-type-is-not-derivable).

```tsi
// not-checked — WRONG
export infer function topLabel(.index: Map<string, number>) {
  return ask `the label with the highest count`: string;
}
```

```tsi
// top-label.tsi — RIGHT
export infer function topLabel(.index: { label: string; count: number }[]) {
  return ask `the label with the highest count`: string;
}
```

## NOLA2010

> Nola constructs are not allowed inside a context statement or an instruction literal's hole; a hinted call intent used as a value must be parenthesized.

**Cause:** `` ..`…` `` or `ask` inside a context statement — as a parenthesized value, nested in a bracketed value or in a `${}` hole of its text — or inside a `${}` hole of a call hint. A context statement is read at each ask with no frame of its own, and a call hint is re-emitted from source. A call intent is a legal value, but a hinted one, `` fn`hint`(…) ``, written bare is read as the value `fn`, then the text `hint`, then a parenthesized group: its `` ..`…`: T `` argument is the bare extractor this code reports (written without the dots, `` (`…`: T) ``, the same group is a syntax error at the colon, since a parenthesized group has no slots). Written directly after the text, a bare `ask` or `..` is [`NOLA1020`](/docs/reference/error-codes/#nola1020) instead.
**Fix:** compute the value first and interpolate the result, or move the ask into the function body. To use a call intent with a hint as a value, parenthesize it or write it in a `${}` hole; a plain call with an extractor argument needs no parentheses.

```tsi
// not-checked — WRONG
declare function escalate(team: string): void;

export infer function route(.ticket: string) {
  `If the ticket is an outage,` escalate`page the on-call engineer`(..`the team to page`: string)
  return ask `the label for the ticket`: string;
}
```

```tsi
// route.tsi — RIGHT
declare function escalate(team: string): void;

export infer function route(.ticket: string) {
  `If the ticket is an outage,` (escalate`page the on-call engineer`(`the team to page`: string))
  return ask `the label for the ticket`: string;
}
```

## NOLA2011

> exported type '…' would also become a value, but a value named '…' is already declared in this file — rename one of them

**Cause:** every exported type alias and interface in a `.tsi` also becomes a runtime value under the same name ([Types as values](/docs/language/types-as-values/)), and this file already declares a `const`, `let`, `var`, `function`, `class` or `enum` with that name.
**Fix:** rename the type or the value.

## NOLA2012

> property 'age' of Signup: @minLength applies to strings, not to number

**Cause:** a JSDoc constraint tag ([Constraints](/docs/reference/schema-derivation/#constraints)) does not fit — the keyword is for another kind of type, its value is missing or not a number, the `@format` name is unknown, the `@pattern` is not a valid regular expression, or the tag is given twice. Raised at the type for every kind of site (exported type, extractor, contextual parameter); the contextual-parameter policy does not apply, and prune mode does not drop the member.
**Fix:** move the tag to a member of the right kind, or correct its value.

## NOLA2014

> a typed template literal is an extractor only directly after `ask` or in a call's argument list; write `` ..`…`<T> `` here.

**Cause:** a template literal with type arguments — `` const i = `x`<string> `` — somewhere other than directly after `ask` or in a call's slots (a direct argument, or a value nested in object/array literals there). The two dots are implied only in those two places; elsewhere a bare template is an ordinary string, so an extractor there needs its sigil ([Two spellings, one construct](/docs/language/extractors/#two-spellings-one-construct)). The colon spelling has no such code: `` const i = `x`: string `` is an ordinary syntax error.
**Fix:** write `` ..`x`: T `` (or `` ..`x`<T> ``) — for a stored intent, or an extractor under a ternary, a spread or `new`.

## NOLA2015

> Dept: Choice needs 2 to 255 labels, got 1

**Cause:** the criteria of a decision type are malformed — a `Choice` argument that is not a label union or a `{ label: description }` type literal of string literals and `null`, fewer than 2 or more than 255 labels; a `Scale` argument that is not a tuple of 2 to 10 string literals; a `Prob` argument that is not exactly `{ true: "…"; false: "…" }`. Raised at the type for every kind of site (exported type, extractor, contextual parameter); the contextual-parameter policy does not apply, and prune mode does not drop the member.
**Fix:** write the criteria as literals: `` Choice<{ billing: "Payments"; sales: null }> ``, `` Scale<["Calm", "Angry"]> ``, `` Prob<{ true: "…"; false: "…" }> ``.

## NOLA2017

> a context statement is only legal in a scope body — directly in an infer function or at module level. · a context statement cannot be the unbraced body of an `if`, a loop or a label — wrap it in braces.

**Cause:** a bare template literal statement inside a plain function, a callback (even one written inside an infer function), a class static block or a namespace body, or as the unbraced body of an `if`, `else`, loop or label (`` if (x) `text`; ``). No `ask` can run there, so nothing could carry the text to the model.
**Fix:** move the statement directly into the infer function's body or the module body, put braces around an unbraced body, or make the text a plain string if it was never meant for the model.

```tsi
// not-checked — WRONG
export infer function go(.items: string[], urgent: boolean) {
  items.forEach((it) => {
    `note` it;                              // a callback: no ask can carry it
  });
  if (urgent) `Answer quickly.`;            // an unbraced body
  return ask `a summary`: string;
}
```

```tsi
// go.tsi — RIGHT
export infer function go(.items: string[], urgent: boolean) {
  `items:` items;
  if (urgent) {
    `Answer quickly.`
    return ask `a short summary`: string;
  }
  return ask `a summary`: string;
}
```

## NOLA2018

> 'n' is not callable (its type is number) — a tool list holds functions, or groups of them.

**Cause:** an entry of a tool list that is neither one function nor a group — a value, a type-only import, a class, a union of function types, `any`; a function under a spread; a group reached through an expression (`[groups[0]]`) instead of a name; a method reached through a call (`api.client().search` — the object would be evaluated again to bind the method); a group with no function-valued member or a member the walk cannot use; or two tools that would share one name on the wire: the same function listed twice, `a.b` beside `a_b`, a spread's `search` beside another `search` (a model's tool call comes back by that name, so the vendors' `[A-Za-z0-9_-]` names must stay distinct).
**Fix:** name a function or a group — `` ask `find the files` [searchFiles, fileTools]: string[] `` — spread a group to flatten it, offer colliding groups bare so their names carry the prefix, and give the functions one declared signature. A parameter the walk cannot derive (a `Map`, a generic parameter, a rest parameter) is [`NOLA2002`](/docs/reference/error-codes/#nola2002) at the entry. Every list of one [ask sequence](/docs/language/tool-use/#several-lists-your-words-between-them) shares one name space; the same written entry in two lists is one tool.

## NOLA2019

> offering tools beside a call is reserved for a future Nola version — offer the function as a tool, `[createUser]`, or make the call a separate ask.

**Cause:** an [ask sequence](/docs/language/extractors/#values-in-the-instruction) that offers tools and also holds a call with typed slots, `` ask `use` [searchFiles] `then` createUser(`id`: string) `` — the kind where the loop runs and the call's slots are the answer, designed but not built; or a `..` sequence written inside a call's slot, `` fn(..`t` user: string) ``, since a slot's instruction is a schema description.
**Fix:** offer the function as a tool, make the call its own ask after the tool-use ask, and keep a slot to one text.

## NOLA2020

> an ask makes one call — split the asks.

**Cause:** an [ask sequence](/docs/language/extractors/#values-in-the-instruction) that cannot mean one thing: two calls with typed slots; a `: T` beside a call (the call's result is the type); text after a bare call, `` ask f(`x`: string) `more` ``; a call with typed slots inside a data value, `` ask `use` (createUser(`id`: string)) `go`: T ``.
**Fix:** one call per ask, no `: T` on a call, the words before the call, the call written bare between texts.

## NOLA2021

> the Nola compiler failed on this file: … This is a Nola bug — please report it with the file's contents; the editor keeps serving the last successful compile.

**Cause:** the compiler threw while lowering the file — an internal error, never something written in the file. The editor reports it here instead of stopping: the language server keeps running on the file's last successful compile, so completion and navigation are approximate until the next successful one.
**Fix:** nothing in your code — report the bug with the file's contents. A build (`nola build`, `nola check`, `nola run`) fails on the same file with the error and its stack, which is what to include.

**Runtime errors (NOLA3xxx)**

## NOLA3001

> This module was compiled for Nola emit contract N, but @nola-lang/runtime (at …) provides contract M. …

**Cause:** lowered code and the installed runtime disagree on the emit contract — a stale build or mismatched package versions.
**Fix:** the message says which: rebuild with the current `nola-lang`, or update `@nola-lang/runtime`. Keep the lockstep packages on one version.

## NOLA3002

> Two incompatible copies of @nola-lang/runtime are loaded: … Run `npm dedupe`, or align your nola-lang versions so a single runtime is installed.

**Cause:** two runtimes with different emit contracts in one process.
**Fix:** `npm dedupe`; align every Nola package to the same version.

## NOLA3003

> *(one of several config messages, e.g.)* `a model map must include a default entry.` · `unknown config key x — allowed keys: …` · `Nola configuration is frozen after the first ask — call nolaRuntime.reset() before reconfiguring.` · `fallback([]) needs at least one model.` · `fallback() cannot wrap nola — the platform model can only be the root: it manages its own resilience (nola.infer({ retry }) for transport retry; routing and failover live on the server). record()/replay() remain available.`

**Cause:** invalid config, reconfiguration after the first ask, an empty provider list, or an attempt to wrap the platform model in `withRetry`, `fallback` or `roundRobin`.
**Fix:** follow the file and field named in the message. See [Config schema](/docs/reference/config-schema/) and [Providers API](/docs/reference/providers-api/#nola).

The related message "No Nola model configured" is a `NolaConfigError` without a code. It means no config was loaded. Use `nola run` or the loader with a `nola.config.ts`, or call `nolaRuntime.configure(…)` before the first ask.

## NOLA3004

> forceModel "x" does not name a configured model — configured: … · .withModel() "x" does not name a configured model — configured: …

**Cause:** `forceModel`, `ask with <name>` or `.withModel("name")` names a key that is not in the `model` map. When the platform serves inference — `model: "nola"` — an ask-site name that matches no key is not an error: it is sent to the platform as an inference profile instead, so this code then fires only for `forceModel`.
**Fix:** add the model to the map, fix the name, or let the platform serve (`model: "nola"`) so free-form names route through it.

## NOLA3005

> `plugins` is reserved for a future Nola version.

**Cause:** a `plugins` key in the config.
**Fix:** remove it.

## NOLA3006

> `cache must be an object — write cache: {} or cache: { store: <NolaCacheStore> }.` · `cache.store is not a NolaCacheStore (need { get(fingerprint), set(fingerprint, value) }).`

**Cause:** a malformed `cache` section. Cache settings are validated but currently have no effect.
**Fix:** use `cache: {}` or a store with `get` and `set` methods.

## NOLA3007

> replay ledger … cannot be read: … · replay ledger …:N is not valid JSON. · replay ledger …:N is missing fingerprint or response.text. · replay() needs a file system for its ledger — …

**Cause:** the JSONL ledger given to `replay(path)` is missing, unreadable or malformed; or `record(…)` / `replay(…)` was called where there is no file system (a browser, or a Node older than 22.3 — the message says which).
**Fix:** check the path; re-record the ledger; on a browser host, record and replay on Node and bring another model to the browser. See [Record and replay](/docs/config/record-and-replay/).

## NOLA3008

> replay ledger … has no entry for fingerprint … — the prompt, schema, or context changed since the ledger was recorded. Re-record it.

**Cause:** no recorded request matches the current prompt, contextual values, schema, params or inference profile. The provider name alone does not affect the match.
**Fix:** record the changed requests (`NOLA_RECORD=1` with the setup in [Record and replay](/docs/config/record-and-replay/)), or switch to a live provider.

## NOLA3009

> this type cannot be used in an intent schema: …

**Cause:** an underivable type reached an ask at run time (a companion module marked it `unsupported`).
**Fix:** as for `NOLA2002` — use a JSON-shaped type.

## NOLA3010

> extract/call intents carry no construction scope — only `ask` supplies their frame.

**Cause:** a raw extractor or call intent was awaited or run outside `ask`, often from plain TypeScript.
**Fix:** resolve it with `ask` inside an infer function or at module level in a `.tsi` file. From plain TypeScript, `await` the infer function's result.

```ts
// not-checked — WRONG: nothing supplies the inference context
import { nameIntent } from "./person.tsi";
const name = await nameIntent;
```

```tsi
// person.tsi — RIGHT
export const nameIntent = ..`the user's full name`: string;

export infer function whoIsIt(.text: string) {
  return ask nameIntent;
}
```

**Cause:** `nola.config.ts` (or something it imports) imports a `.tsi` file.

**Cause:** an ask ran where `window` and `document` exist.

## NOLA3015

> the Nola loader needs Node.js module hooks, which Bun 1.3.14 does not run. Run .tsi on Bun with @nola-lang/bun: add `preload = ["@nola-lang/bun/preload"]` to bunfig.toml and run `bun src/main.tsi`. Or run on Node: `npm start` / `bun run start` (the nola bin runs on Node) or `node --import nola-lang/register src/main.ts`.

**Cause:** the Node loader (`nola run`, `node --import nola-lang/register`) was started under Bun or Deno.
**Fix:** on Bun, use the [Bun plugin](/docs/tooling/bun/) — `.tsi` then loads from source without Node's loader; on Deno, run on Node (≥ 22.18). Any package manager is fine.

## NOLA3016

> value does not match …: …

**Cause:** `parse()` on a type value rejected the input; the thrown `NolaValidationError` carries the structured `issues`.
**Fix:** validate with `validate()` when rejection is expected, or fix the input. See [Validate and parse](/docs/language/types-as-values/#validate-and-parse).

## NOLA3017

> JSON Schema target '…' is not supported (expected one of 'draft-2020-12', 'draft-07', 'openapi-3.0')

**Cause:** a Standard JSON Schema consumer asked `User["~standard"].jsonSchema.input()` / `.output()` for a dialect Nola does not emit. The spec requires a library to throw rather than hand back the wrong dialect.
**Fix:** pass one of the three supported targets. See [Standard Schema](/docs/language/types-as-values/#standard-schema).

## NOLA3018

> output property "department" is a Choice; model "openai" cannot answer decision questions — route the ask to a decision model (`ask with <name>`) or use the plain form (a literal union, or boolean).

**Cause:** the output type contains `Choice`, `Scale` or `Prob`, but the selected model does not support decision questions. Nola rejects the ask before sending a request because those types require probabilities from a decision model. A `fallback` or `roundRobin` group supports decisions if at least one member does; other members are skipped for decision asks.
**Fix:** select a decision model with `ask with <name>` or `.withModel()`. If you only need a label or yes/no answer, use a literal union or `boolean`.

## NOLA3019

> this ask offers tools (search, readFile); model "mock" cannot request tool calls — route the ask to a model with tool support (`ask with <name>`), or write the ask without a tool list.

**Cause:** an ask with a tool list — `` ask `find the files` [searchFiles, readFile]: string[] `` — resolved to a model that cannot return tool calls: a hand-written `LanguageModel`, a mock without `{ tools: true }`, a provider without tool support, or a vendor model configured with `toolUse: false`. Nola refuses before the network, since the loop has nothing to run.
**Fix:** route the ask to a model that supports tool calls (`ask with <name>` or `.withModel()`), brand a mock with `mockProvider(…, { tools: true })`, or write the ask without the list. A `fallback` or `roundRobin` group supports tool use if at least one member does; other members are skipped for tool-use asks. See [Tool use](/docs/language/tool-use/#models).

## NOLA3020

> tool use at src/find.tsi:3:19 exceeded 10 turns without an answer (`.withMaxTurns(n)` or config ask.maxTurns raise the cap).

**Cause:** the model kept requesting tool calls past the turn cap — `.withMaxTurns(n)` on the intent, else config `ask.maxTurns`, 10 by default. Each provider call is a turn; the single correction turn after a bad answer is not counted.
**Fix:** raise the cap when the task legitimately needs more lookups, give the model tools that answer in fewer calls, or sharpen the task text. The error carries the transcript so far. The failure is definitive: `.withRetry(n)` re-runs the whole loop, tools included.

## NOLA3021

> tool "readFile" threw during tool use at src/find.tsi:3:19: ENOENT: no such file

**Cause:** a tool the model called threw or returned a rejected promise. A thrown error ends the ask — nothing is swallowed — with the error as the `cause` and the transcript so far attached.
**Fix:** fix the tool, or, when the model should be able to recover from the failure, return it as a value (`{ error: "no such file" }`) instead of throwing — the model sees every returned value. Invalid arguments never reach the function: the validation issues go back to the model as that call's result.

## NOLA3022

> the tool list at 3:19 cannot be built: 'fileTools.search' is not a function (got undefined).

**Cause:** when the ask ran, a tool list entry did not match what its type promised — a group member that is not a function, an array with a different length, a value that is not a function — or a tool had no name (an anonymous function in an array), or two tools shared one wire name. Raised before any provider call.
**Fix:** keep the value and its type in step (a module's exports, a `const` tuple), name the functions, and offer groups bare when two of them share a member name. See [Tool use](/docs/language/tool-use/#the-tool-contract).

## NOLA3023

> Bun >= 1.3.0 is required by @nola-lang/bun (process.getBuiltinModule is missing in Bun 1.2.0). Upgrade Bun: `bun upgrade`.

**Cause:** `@nola-lang/bun` (the preload or `nola()`) started under a Bun older than 1.3, which lacks `process.getBuiltinModule` — the only way the runtime reaches Node builtins.
**Fix:** upgrade Bun (`bun upgrade`). See [Bun](/docs/tooling/bun/).
