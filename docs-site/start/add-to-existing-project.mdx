You have a TypeScript project; this adds `.tsi` support to it without scaffolding a new one.

## Run the retrofit

```sh
npm create nola -- --add
```

A bare interactive `npm create nola` offers the same thing when it finds a `package.json` in the current directory ("Add Nola to this project"). `--add` and `--template` are mutually exclusive — the first retrofits, the second scaffolds. (`nola init --add` is the identical flow, but it lives in the `nola-lang` package — so it only exists once that is installed; `npm create nola` is the form that works from nothing.)

Optional flags, all also offered interactively:

- `--ide vscode` writes `.vscode/launch.json` (F5 debugging of `.tsi` files) and `.vscode/extensions.json` (recommends the Nola extension) — see [Editor setup](/docs/start/editor-setup/).
- `--agents claude,cursor,copilot,agents-md` writes the Nola skill into the project for your coding assistant — self-contained, version-stamped files (Claude Code gets the whole skill directory; Cursor, Copilot and `AGENTS.md` get the skill body inline). `nola skill install` does the same later, and `nola skill install --force` refreshes them after an upgrade.
- `--provider nola|openai|anthropic|google|none` answers *Select an inference provider:* (asked first interactively; `--trial` / `--no-trial` are shorthands for `nola` / `none`). `nola` takes the 25 free Nola API runs: the retrofit requests an anonymous key, writes `NOLA_API_KEY` into `.env` (appended if the file exists, never overwriting an existing entry), makes sure `.gitignore` lists `.env` and `.env.*`, and — when it wrote the config — uses `model: nola.infer()` (the platform serves inference). If this machine already took the free runs, choosing Nola signs you in (browser) and mints the key on your Nola account instead of a second trial. A vendor writes that vendor's config instead (its key stays yours to put in `.env`). An existing `nola.config.ts` is left alone with a note naming the `model:` line to set yourself.

## What it writes, merges, and leaves alone

| | Files | Detail |
| --- | --- | --- |
| **Written** | `nola.config.ts` | The chosen provider's config: `model: nola.infer()` for Nola, `openai("gpt-5-mini")` / `anthropic("claude-sonnet-4-5")` / `google("gemini-2.5-flash")` for a vendor (each with an offline `mockProvider` alternative in a comment); `none` writes the OpenAI one. Skipped — and left untouched — if one already exists. |
| **Merged** | `package.json` | Adds `@nola-lang/runtime` and `@nola-lang/providers` to `dependencies`, `nola-lang` and `typescript` to `devDependencies`. The Nola packages get the same lockstep version; `typescript` gets `^5.6.0`. Existing entries are never rewritten, and the file is only touched when something was added. |
| **Suggested, not touched** | `package.json` scripts, `tsconfig.json` | The command prints its next steps: install the packages, an optional `"start": "nola run src/main.ts"` script, and the tsconfig tip below. |
| **Untouched** | everything else | Unless Nola is the provider nothing else is read or written; with it, `.env` and `.gitignore` are appended to as described above. |

Then run your package manager's install.

## tsconfig requirements

```jsonc
// tsconfig.json
{
  "compilerOptions": {
    "strict": true,
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "allowArbitraryExtensions": true,
    "noEmit": true,
    "skipLibCheck": true
  },
  "include": ["src"]
}
```

Three settings matter for Nola:

- **`module` / `moduleResolution`: `NodeNext`** — plain-TS imports use the `./x.js` specifier (even though the file on disk is `x.ts`); `.tsi` imports keep their literal extension.
- **`allowArbitraryExtensions: true`** — required so TypeScript accepts the declaration pairs Nola emits for `.tsi` modules.
- **`include` is directory-style** — `["src"]`, never `["src/**/*.ts"]`. The directory form lets the editor tooling admit `.tsi` files into the program while plain `tsc` ignores them; under the glob form `.tsi` files fall out of the program and auto-import stops offering your infer functions.

## First .tsi file

```tsi
// src/hello.tsi
export infer function summarize(.text: string) {
  return ask ..`a one-sentence summary`<string>;
}
```

```ts
// src/main.ts
import { summarize } from "./hello.tsi";

console.log(await summarize("Nola is a TypeScript superset where asking an LLM is part of the language."));
```

```sh
npx nola-lang run src/main.ts    # run with the loader and nola.config.ts applied
npx nola-lang check              # type-check .tsi and .ts together
```

## Existing build pipelines

Plain `tsc` cannot parse `.tsi`; `nola check` is the type-check path and `nola build` the compile path. If a `tsc` or framework build must *resolve* `.tsi` imports (for example `next build` or `tsc --noEmit` in CI), keep `allowArbitraryExtensions` on and run `nola declarations` to write adjacent `<name>.d.tsi.ts` files (gitignore them — the editor hides them next to a live `.tsi`, and `nola check` ignores them). The bundler plugins (`@nola-lang/vite`, `webpack`, `rollup`, `rolldown`, `esbuild`, `rspack`) and `@nola-lang/next` do the lowering inside the bundler instead — see [The nola CLI](/docs/tooling/cli/).
